# Q20：最小数据发布规则分析

日期：2026-08-11

## 结论

**不采用 L1–L5 数据等级。** 它把来源可信度、位置精度、审核状态、路网完整度和无障碍信息压成一个序数，但这些维度彼此不能替代：一条有官方来源的线仍可能不是入口，一枚位置精确的社区图钉仍可能未审核，一条普通可走路线也不能因此称为无障碍。

当前只需要一条公共事实边界和两个按能力失败关闭的护栏：

1. **公共事实边界**：沿用现有领域规则——获批准的 Map fact 可以公开；Map change request / Pin application 在批准前不进入默认地图、搜索、附近结果或路线计算。草案可以出现在明确标示的审核/研究视图中。
2. **位置护栏**：产品只显示数据实际证明的定位精度；知道建筑就停在建筑，知道楼层就停在楼层，只有获得可公开使用的楼层几何和室内点位后才画精确室内图钉。
3. **路线护栏**：只有起终点接入和整条路径均已核实，且没有经过候选吸附、工作图边或未知的关键通行条件时，才提供逐步导航；否则退化为地点信息、建筑/楼层定位或明确命名的参考路线。

无障碍和实时开放状态不是额外“等级”，而是更强的产品声明：任一路段的相关字段未知，就不能作出该声明。

这比 L1–L5 更小，也更符合现有 [CONTEXT](./CONTEXT.md)、[ADR 0013](../adr/0013-campus-map-facts-before-art.md)、[ADR 0014](../adr/0014-campus-map-portals-and-physical-network.md) 和 [ADR 0015](../adr/0015-campus-map-three-graph-layers.md) 已经建立的事实边界。

## 为什么当前数据不支持一把尺的等级制

当前 [pilot gold set](../../src/lib/campus-map/generated/pilot-gold-set.json) 同时出现了几种完全不同的“可用”：

- 86 栋建筑全部完成官方目录对账，因此可以作为建筑目录或搜索候选。
- 2,009 条政府行人线段均有几何和来源，但物理网络有 16 个连通分量。
- 86 栋建筑共有 258 个入口吸附候选，人工批准数为 0；其中 144 个是 `needs-survey`。
- 工作地点图有 87 个节点、124 条边并被算法连成 1 个分量，但它只取最大原始分量、遗漏另外 15 个分量，使用 MST + nearest-neighbor 派生关系，并含 2 个回退接入。
- 118 条线段标为室内，只有 3 条带非空 `floorId`，不足以支撑普遍楼层导航。
- 数据集因此正确保持 `release.status = blocked`。

若使用单一等级，以上事实会产生错误升级：几何和 provenance 覆盖率 100% 并不使入口候选成为入口；工作图的单分量也不使原始网络完整。相反，全局 `blocked` 也不应阻止已经获准的建筑或独立设施点用于搜索和展示。

因此应发布**具体能力**，而不是给整套数据或每个要素颁发综合等级。

## 最小规则

### 规则 1：默认产品只消费已发布 Map fact

一个地点或设施进入默认地图、搜索和附近结果前，最低需要：

- 稳定身份和类别；
- 一个可说明的实际位置范围；
- 来源记录或贡献者的原创现场观察，以及核对日期；
- 对所展示文字、图片和几何具有公开使用权；
- 通过现有管理员批准流程。

这不是要求每条事实都来自校方。官方来源、开放数据和社区实测可以支持不同事实，但都要明确“该来源实际证明了什么”。评论与评分只可附着到已发布 Place，且不能让地点自动通过事实审核。

候选、机器派生和待现场核实资料仍然有价值，但只出现在持续标明“候选/审核用”的视图中。不能只靠一次免责声明就把它们混进默认地图。

### 规则 2：位置精度不升级

位置不需要 L1–L5；使用数据本身的落点类型即可：

| 已知事实              | 可以公开的体验             | 禁止的升级                    |
| --------------------- | -------------------------- | ----------------------------- |
| 建筑名 + 建筑锚点     | 建筑搜索、显示建筑大致位置 | 把锚点称为入口或房门          |
| 建筑 + 楼层           | 搜索结果显示“某楼某层”     | 在没有室内坐标时伪造楼层图钉  |
| 获授权楼层图 + 室内点 | 楼层切换和精确设施图钉     | 从仅供参考的 PDF 擅自描摹几何 |
| 已核实 Portal         | 把建筑接入物理路网         | 从最近线段自动生成入口        |

搜索允许部分结果：若课室只定位到建筑和楼层，就清楚显示“房门尚未测绘”，而不是隐藏整个课室，也不是画一个看似精确的点。

“附近”只比较具有可比较坐标的地点。MVP 若使用直线距离，必须写明“直线距离”；没有地理配准的室内本地点不参加跨建筑距离排序。

### 规则 3：路线必须逐条满足路径门槛

当前无需为每条边设计五级状态，也无需要求整个校园先成为一个连通分量。一次用户路线可以公开为逐步导航，当且仅当：

1. 起点和终点都接到已核实的 Portal / 路由节点；
2. 路径只使用 Physical graph 的有来源真实边，不使用 Display graph、Art geometry、MST / nearest-neighbor 地点边或候选 snap；
3. 路径上的方向、楼层转换和垂直设施足以生成不误导的指示；
4. 路径不跨越未核实的 scope boundary、component seam 或室内外 seam；
5. 与本次请求相关的访问限制没有未知值。例如请求“轮椅路线”时，台阶、门槛、电梯和开放条件任一未知即失败。

失败是正常产品结果，不要自动补线。退化顺序为：

1. 显示目标的已知建筑/楼层；
2. 可选择显示有明确来源、日期和限制的官方/审核参考路线；
3. 告知该区段暂未提供可靠逐步导航。

在真实可路由数据到来前，最小实现可以只发布人工选定并验收的参考路线，不开放任意两点最短路。这样无需现在发明完整的 per-edge 发布状态机。

### 规则 4：未知不能被产品文案变成肯定

以下声明必须失败关闭：

- 没有当前状态来源时，不显示“现在开放”“设备正常”；改为显示已知开放规则或最后核对日期。
- 没有完整路径属性时，不显示“无障碍”“无楼梯”；`unknown` 不是 `false`，也不是 `true`。
- 未知方向不能被当作双向；未核实入口不能被当作正门、全天入口或访客入口。
- 社区评论中的“今天坏了”“可以走”可以作为带时间的报告，不能直接改写 Map fact 或路线资格。

现在不必为每类设施设统一过期天数。先强制保存和展示 `checkedAt` / 来源日期；等真实更新频率出现后，再按类别制定刷新策略。

## 各产品能力现在可以怎样发布

| 能力              | 最低可发布条件                                              | 当前结论                         |
| ----------------- | ----------------------------------------------------------- | -------------------------------- |
| 建筑/设施图钉     | 事实获批、来源/观察和核对日期齐全、位置精度诚实、重用权清楚 | 可逐条上线，不等待全校园完整     |
| 课室搜索          | 建筑和房间代码获批；楼层未知时明确降级                      | 可以先做到建筑或楼层             |
| 楼层视图          | 楼层编号关系明确，图稿/几何获公开使用权                     | 只在已获授权或原创测绘的楼宇上线 |
| 评论/评分         | 对应 Place 已发布；评论与事实分离并可举报                   | 不依赖路网完整度                 |
| 附近设施          | 候选点有可比较地理位置，并标明直线或路线距离                | 室外点可先做直线距离             |
| 参考路线          | 有明确来源/版本或完成逐条人工验收，持续显示限制             | 可局部上线                       |
| 任意两点逐步导航  | 满足整条路径门槛                                            | 当前 pilot 不满足                |
| 无障碍导航        | 普通路径门槛 + 路径上所有相关可达属性已明确核实             | 当前不发布                       |
| 实时开放/设备状态 | 有可识别的当前状态源和更新时间                              | 当前不作实时声明                 |

## 对现有 `release.status = blocked` 的处理

保留它作为 **pilot 路网数据集的 QA 结论**，因为四个 blocking reasons 都真实存在。不要把这个字段扩展成整个 Campus Map 产品的总开关：

- 它应继续阻止 pilot 工作图进入逐步导航；
- 它不阻止独立获批的 Place、课室目录、评论或楼层试点公开；
- 审核页面仍可展示候选网络，但必须与默认产品入口分开并持续标为 blocked/draft。

未来若只修复一个建筑或一条走廊，也可以只发布该范围的能力，不必等 16 个原始分量全部合并。全校园连通率是数据 QA 指标，不是所有地图功能的前置条件。

## 可以安全推迟的决定

在看到第一批真实社区图钉、获授权楼层图和经过审核的路线前，不决定：

- L1–L5 或任何综合置信度等级；
- 官方、开放数据和社区来源的全局分数排序；
- 每类设施统一的过期天数；
- “需要几人确认”或照片数量等固定审核阈值；
- 全校园覆盖百分比、单一连通分量或全部建筑入口作为产品总发布门槛；
- 完整 per-edge 发布状态机、路径算法和室内坐标标准；
- 自动无障碍评分或“认证”语言；
- 社区信誉分、投票加权和自动晋级规则。

这些决定需要真实数据分布和运营反馈。现在提前固定只会把暂时假设变成迁移成本。

## 建议写入领域规则的一句话

若本分析获采纳，后续只需在 CONTEXT/ADR 补充这一条，而不引入等级体系：

> Campus Map 按能力发布：获批准且位置精度诚实的 Map fact 可以独立公开；逐步导航仅在起终点接入及整条物理路径均满足本次通行模式的已核实条件时提供，任何关键未知都必须降级而不是推断。

这条规则保留了协作地图“资料不完整也能逐步成长”的价值，同时把最可能伤害用户信任的三类错误——假精确位置、自动补出的路线和未经证实的无障碍/实时声明——明确挡在公开产品之外。
