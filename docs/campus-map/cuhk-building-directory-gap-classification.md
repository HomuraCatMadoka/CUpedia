# CUHK 楼宇目录相对 2016 快照的 26 项差异分类

状态：研究快照

最后核对：2026-09-04

## 结论先行

这 26 个编号不是 26 栋应直接补进生产地图的普通楼宇。[CUHK Campus Development Office
（CDO）楼宇目录](https://cuhk.edu.hk/cdo/bldgdir.htm)把楼宇、游泳池、花园、广场、发电机、候车亭、危险品仓、
后勤设施和施工项目放在同一张表里。目录编号只能证明“校方用这个编号指一个校园对象”，不能单独证明它是用户可见的
Building。

这 26 项也不是“高德可点击卡片清单”。它们只是 2024 CDO 目录相对仓库 2016 楼宇快照的差异；
实际映射覆盖率必须另从生产高德底图的 `hotspotclick` 对象 ID 盘点，不能用本表代替。

按当前证据，建议是：

- 立即补成 active Building：3 项（U9、IH4、IH5）。
- 只记录为 construction、暂不进入 active 浏览：4 项（A5、A9、S7、YS4）。
- 属于实体后勤建筑，但当前学生地图无需公开：5 项（H10b、H31a、E5b、E6、E7）；H31a 还缺正式名称和当前用途核对。
- 应建模为 Place / 公共设施，而不是 Building：6 项（H1a、H8b、E12、C29a、N7a、U11a）；其中 H1a、E12
  已有可重复检索的高德 POI 证据，应进入 active Place 修复队列，其余四项暂缓。
- 属于基础设施，不应成为普通 Building 卡片或“添加设施”目标：6 项（H8a、H10c、H31b、C13a、O1、O2）。
- 名称、代码或完成状态不足以确定身份：2 项（C33、O3），暂缓。

当前 `campus_map_buildings` 没有 lifecycle 或 public visibility。只要插入一行，它就可能进入搜索、卡片和浏览投影。因此，
在增加 `active / construction / hidden / retired` 等最小状态之前，不应把施工项目和后勤资产导入现有表，再期待 UI 另行猜测是否显示。

## 判定标准

本报告分别回答两个问题：

1. 现实中是否是可以拥有稳定身份的物理建筑；
2. 现在是否应成为学生地图上的 active Building，可被搜索、打开卡片并作为“添加设施”的容器。

“CDO 有编号”不是第二个问题的充分条件。面向学生的地图只应默认公开已经启用、可以作为校园目的地或设施容器的建筑。
花园、广场、露天剧场和泳池可以是独立 Place；发电机、危险品仓和废物设施即使有实体结构，也不应自动成为普通 Building
卡片。施工项目可以预留身份，但不能冒充已经开放的建筑。

高德是否提供可点击卡片是第三条独立证据轴，不等同于现实对象类型。2026-09-04 在生产地图和高德网页实测：科学馆、
大学保健医疗中心等不同类型对象点击后都使用相同的“高德地图地点”临时卡；高德检索还为游泳池返回类别“游泳馆”。
因此“有高德卡片”只能说明它是 provider POI 候选，不能说明它是 Building；经过官方来源核对后，它可以升级为 canonical
Building 或 canonical Place。

### 2026-09-04 高德实测摘要

- 生产地图点击 ScienceCentre 科学馆和大学保健医疗中心，都会打开同一种只有标题与“高德地图地点”的临时卡，说明该卡
  不是 Building 专用卡。
- 高德网页可打开独立“游泳池”详情，类别为“游泳馆”；这足以把 H1a 放进 canonical Place 修复队列。
- 高德检索可分别返回“香港中文大学科学馆北座高锟楼”和“香港中文大学科学馆南座马临楼”，进一步反证把两者压成 H10
  检索名称的做法。
- 高德精确检索可返回 E12 金禧校友园；本次没有返回 H8b 金禧承泽园、铭泽楼、合一亭、思源广场、C29a 入口广场、U9
  蔡继有宿舍、IH4 或 IH5 的同名结果。没有返回不是“不存在”的证据：U9、IH4、IH5 均有更强的 CUHK 当前官方资料，
  这也证明高德覆盖本身不完整，不能反向决定 canonical 身份。

## 对导入工作的直接建议

### 现在可以做

1. U9 建立新的 active Building identity，并使用已核实的独立锚点。
2. IH4 延续旧 H19 的 canonical ID，更新当前主名和代码；H19 保留为历史编号，不作为第二栋楼。
3. IH5 建立 active Building，但先核对 H18 旧锚点是否确实落在现在的五座，再决定是否复用旧 ID。
4. H1a 游泳池和 E12 金禧校友园建立 active Place；先增加准确的受控 pin type，不能硬塞进 `common-space`。

### 当前不要做

- 不要把 26 行机械插进 `campus_map_buildings`。
- 不要把花园、泳池、广场和露天剧场伪装成 Building；它们若进入地图，应走 standalone Place。
- 不要为发电机、候车亭或危险品仓开放普通卡片和“添加设施”。
- 不要仅因预计竣工日期已经过去，就把 A9 或 S7 改成 active；要有官方交付或实际启用证据。
- 不要把 C33 推断成当前 Block E 项目，也不要把 O3 推断成 H46 的别名。

### 若以后需要完整资产目录

H10b、E5b、E6、E7 现实中有实体建筑性质，可以拥有稳定 canonical identity。但这不要求它们出现在学生默认地图。
最小做法是在 Building 上增加生命周期和可见性，而不是为不同类型各造一套表：

- lifecycle：`construction | active | retired`；
- browse visibility：`public | hidden`。

在产品出现“需要把一个 Place 归属到这些后勤建筑”或“管理员要维护完整建筑资产”之前，可以继续不导入它们，避免预建无用复杂度。

## 田家炳堂的本轮边界

田家炳堂可以不纳入这次“修复生产地图现有图标和卡片”的变更，但理由应是 **deferred scope**，不是“它不存在”。
[新亚书院官方资料](https://www.na.cuhk.edu.hk/e_newsletter/opening-ceremony-of-tin-ka-ping-hall/)说明它是梅云堂三座宿舍组合中首座完成的楼；
CDO 目录也把它列在梅云堂下，只是没有独立代码。[2024 官方迎新地图](https://www.orientation.cuhk.edu.hk/wp-content/uploads/2024/08/2024-Orientation-Day_campus_map.pdf)
只显示梅云堂，没有给田家炳堂独立地图标记。因此本轮不创建 marker 是合理的，但不要把“田家炳堂”写成梅云堂 alias，未来取得独立锚点或明确地图需要时再建独立 Building。

## 证据边界

- CDO 旧楼宇目录页显示 Copyright 2024，适合证明名称和编号，不足以单独证明 2026 年的施工或启用状态。
- 项目状态优先使用 2026 年仍在线的 CDO portfolio、施工公告、书院当前页面和当前运营页面。
- 本次没有现场测量，也没有取得正式 GIS footprint；“可立即纳入”仍以取得合格 WGS84 代表锚点为地图发布前提。
- H31a、C33、O3 的正式身份仍未解决；S7、A9 尚未找到官方正式启用或竣工确认。
