# 交通信号推断候选：开源状态与 CUHK 可迁移性

日期：2026-08-09
范围：只核验四组指定候选；来源限论文原文与项目官方仓库。

## 结论

没有一个候选同时满足“许可证明确的开源实现”和“可从 CUHK 现有稀疏 `路线 + 站点 + 到站时间` 反馈直接工作”。最值得借鉴的是 2025 FCD 论文的分层处理思想，但它要求每 3 秒一条车辆轨迹、停止线几何及大量 stop-to-start 事件；这与每次乘客反馈只有一个到站点事件有数量级和语义上的差异。

公开可见、可下载、可依法复用必须分开判断：论文网页公开不代表代码公开；共享盘声称含源码也不等于存在明确 OSS license。当前证据下，前三项均应视为“论文方法”，不能作为已核验的开源软件依赖。SUMO、CityFlow 和 LibSignal 确有公开代码，但解决的是仿真/控制，不是现实信号倒计时推断。

## 2025 大规模 FCD 方法的准确边界

[论文方法部分](https://arxiv.org/html/2507.14190)给出的处理链是：

```text
3 秒 GPS/FCD
→ 去噪、轨迹切分、map matching
→ 停止线距离、越线时间、stop-to-start、等待时长
→ 相同路口/方向的多日数据叠加
→ FFT 产生候选周期 + KS 检验排除半周期/倍周期
→ TOD 滑窗初筛 + dispersion 精定位配时切换
→ 排序等待时长，以局部梯度变化和两段回归的拐点估红灯时长
→ 通行/停车频率投票复核，不可靠结果撤回
```

论文实验覆盖北京、上海、深圳 10,304 个路口，合计约 710 万条有效轨迹，平均每个路口方向约 710 条；公开附件则声称是较小的约 100 路口/72 万条去标识样本。二者不能混称为同一个完整公开训练集。

复现还有一个实质缺口：queue-induced start delay 校准依赖作者的 proprietary link-ranking system，以及按城市、道路等级、时段等形成的历史回归参数。论文称附件包含 supporting/calibration parameters，但共享盘当前无法读取，且没有许可声明。

因此，该论文最多支持以下结论：在高密度、连续、有停止线语义的 FCD 上，这套统计流程可估计半固定信号的周期、TOD 和 phase duration。它不支持“只用站点到站反馈即可恢复实时红绿灯倒计时”。

## 对 CUHK 的具体取舍

可迁移：

- 把原始点击先去重、校验并聚合为一个物理 `ArrivalEvent`，不要把多个用户对同一辆车的点击当独立样本。
- 按 `RoutePattern × Stop × time band × day type/week of term` 多日聚合，先学习长期到站偏移与不确定性。
- 用候选生成、交叉验证、异常撤回和最小样本门槛控制发布；数据不足时明确回退，而不是强制给出“精准倒计时”。
- 如果未来采集同一车辆的连续 GPS，再研究 stop/start、路段速度及当前 `Trip` 状态；届时 Fayazi 的稀疏轨迹重建比直接套用深度网络更合适作为基线。

不可迁移：

- 对点状到站事件做 FFT 或 KS：校巴班次不是同一信号每几十秒重复一次的振荡过程，频谱峰更可能反映班距或课表。
- 从站点到站延误反推单一路口红灯时长：观测混合了行驶、拥堵、站停、上落客和多个路口延误，系统不可辨识。
- 把 SUMO/CityFlow/LibSignal 列为倒计时预测实现：它们可生成或控制已知信号状态，却没有完成 probe observation → inferred real-world SPaT 的逆问题。

## 建议

首版不要引入任何上述仓库作为生产预测依赖。以长期、分层、带不确定性的到站偏移模型处理 `路线 + 站点 + 到站时间`；保留原始事件和候选 `Trip` 关联，以便未来有连续车辆位置时增加在线状态层。交通信号方法只作为事件清洗、条件化聚合和发布质量门槛的设计参考。

若要做下一步可复现实验，应先取得连续 GPS（时间、坐标、速度、车辆/班次伪匿名 ID）及可靠路网/站点几何；只有在能够识别同一车辆跨站或路口的运动后，才值得用 SUMO 生成基准场景并复现 Fayazi 或 2025 FCD 流程。
