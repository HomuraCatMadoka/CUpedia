# ADR 0017：编辑会话草稿与服务器权威冲突

Wiki 编辑把三种状态分开：服务器页面是唯一公开版本；IndexedDB 只保存当前用户、页面、浏览器编辑会话的未确认草稿；实时协作状态留给未来按页面 UUID 建立的 Yjs 文档。客户端草稿不创建服务器“草稿页面”，也不表示产品支持离线编辑。

每条本地记录带 schema 版本、user/document-kind/page/session、服务器 base version、`contentGeneration`、base snapshot、至多一个 `{ id, snapshot }` 结果未知 submission、draft snapshot 和更新时间。`document-kind` 把公开 Page 与同 UUID 的服务器私有草稿隔离；发布后的本地清理即使失败，也不能让公开编辑器读到私有会话。浏览器先以约 250ms debounce 落本地，再以独立的 1500ms debounce 保存服务器。每个网络提交必须先在一次 IndexedDB 写入中同时持久化 base、submission 和当时最新的 draft snapshot，成功后才可发请求；准备失败必须向 autosave 返回错误，不能把本地写入和 submission 标记拆成两个可分别失败的步骤。基线迁移、提交准备和普通 flush 共用同一条 session 状态转换队列，因此 pagehide/visibility flush 不能在提交准备期间误判“没有在途提交”并删除 outbox。确认与拒绝都按 submission ID 做 compare-and-set；相同内容的两次提交仍是不同事件，旧响应不得清除新的 pending。公开 Page 的 submission ID 同时发给服务器，并与页面、revision mutation 在同一 transaction 写入 receipt；只有同一 ID 的重放才算幂等命中，identified pending 在刷新恢复时不得再用页面字段相等推断已提交。普通 draft flush 只更新尾随草稿，不能创建、更换或复活 outbox。所有 base 迁移按 `(contentGeneration, version)` 单调推进，到达较晚的旧响应、poll 或 rebase 不能降低基线。若保存期间又有输入，则结算时原子保留并 rebase 尾随草稿。准备、确认、拒绝或普通持久化中的运行期 IndexedDB 失败都必须进入 storage-error fence；重试从当前内存快照继续未完成的状态转换，不能重新读取较旧磁盘记录并覆盖内存。完全确认后删除 IndexedDB 记录——公开页面和服务器私有草稿都一样，后者的权威恢复来源是 `wiki_drafts`，不是一份干净的本地副本。浏览器 history entry 按 document kind 提供编辑 session id，所以刷新沿用同一草稿，另一个标签页及 draft → page 生命周期则使用独立记录。升级前不含 document kind 或 submission ID 的记录只作为读取兼容：`?draft=1` 路由可明确迁移为 draft；公开路由无法证明来源时先标记为来源不明，若内容或未知提交已经与服务器收敛则直接清理，只有仍有未确认差异时才进入人工恢复，不能静默套用为 Page。旧 key 到新 key 的读取、写入与清理必须在同一 IndexedDB read-write transaction 中完成；任一步失败都整体回滚并保持编辑器暂停，避免旧记录稍后重新复活。

一个已挂载的编辑器 incarnation 是该 session 网络 drain 的唯一 owner；同 key 的新 incarnation 挂载即使旧组件尚未完成异步 continuation，也会原子接管 lease。切页一开始即用外层 `inert` 关闭输入，再把冻结后的最新内容写入 IndexedDB，并在公开页面等待网络 drain；保存失败时解除 fence 并留在原页。旧 owner 已经发出的请求可以按 ID 结算自己的 durable submission，但每个 await 或队列边界后都必须重验 lease，不能再准备请求、rebase、读取当前编辑器快照或把响应投影进 UI。重新挂载的 owner 直接读取 outbox，不等待旧响应，并按 submitted → trailing 的顺序恢复。服务器私有草稿若已用更高版本精确包含 submitted 页面状态，新 owner 必须先在 IndexedDB 中结算该 outbox、保留 trailing，再开放下一次提交；不能只更新恢复 UI 而把旧 submission 留在内存，等旧 owner 的迟到响应制造 `OUTBOX_MISSING`。这样同一 tab 快速切走、切回不会让旧/新编辑器成为两个并发写入者，也不会在最终快照捕获后继续产生无人持久化的新输入。编辑器始终在当前 URL 前放置一个同 URL history guard，并按 URL 幂等复用，避免 React Strict Mode 重挂载堆出多层 guard。Navigation API 只作为补充：浏览器即使实现了该 API，也可能对跨 document 的 Back 返回 `canIntercept = false`；因此不能用 API 是否存在来省略 guard。导航前的本地 flush 一旦遇到 storage-error 必须留在当前页，重试恢复成功后才能继续离开。

编辑器启动分两阶段：先渲染服务器快照，但在 IndexedDB 恢复判定完成前用外层 `inert` 隔离交互；不能切换 Plate editor 实例自身的 read-only 状态。恢复状态必须区分 loading、ready 与 storage error；读取失败不能按“恢复完成”放行，必须保持 inert 并允许重试，以免新输入覆盖尚未读出的记录。恢复期间收到的 BroadcastChannel / focus / visibility / polling 版本只保留最高版本，不得先写入编辑器。若没有本地恢复内容，启动完成后采用该远端版本；若存在 local / submitted 内容，则本地因果链优先，远端差异在保存时通过乐观锁与三方合并处理。干净编辑器从失焦或隐藏状态恢复时，必须在轮询完成并采用最新服务器版本前短暂 `inert`，避免用户基于旧 baseline 开始输入；普通的可见页面定时轮询不得设置该 fence，以免网络延迟周期性中断打字。定时轮询可以更新只有静止光标的干净编辑器，避免下一次顺序编辑基于陈旧 baseline；非折叠选择区以及请求期间发生的 pointer、keyboard、beforeinput 或 drop 交互必须保留并取消本次采用。IME composition 也是本地交互 fence：从 composition start 到最终输入已经投影进 Plate 并标记为 dirty 之前，autosave 不得读取或提交临时组合文本，BroadcastChannel / polling 不得替换编辑器，已经在途的保存响应也必须延后应用。

普通服务器写入递增 `version`；回滚和删除还递增 `contentGeneration`。版本 CAS 失败后，只有同一 generation 的非重叠 Plate block / 页面属性改动可以三方自动合并；稳定块 ID 区分内容相同的重复块，普通文字块允许 ADR 0008 规定的保守 leaf / formatting 合并。旧 generation 草稿不得静默合入已经回滚的正文。

展示投影不能成为可写快照。由父子树等可变外部状态隐藏的 legacy 子页面链接，保存前必须从服务器存储值补回；只有编辑器确实隐藏的块可以补回，用户可见后主动删除的内容不得复活。补回的旧元素可能没有 Plate node ID，进入保存和回执合并前必须为整棵恢复子树补齐稳定且不冲突的身份，不能放宽三方合并器去猜 mixed-ID block 的对应关系。每份编辑快照必须携带生成该快照时实际隐藏的子页面 ID 集合，并随本地草稿、提交、回执响应、轮询和 BroadcastChannel 一起推进；当前格式即使集合为空也必须显式编码 `hiddenChildPageIds: []`，缺少字段只能表示旧格式兼容，不得用来回退到旧的非空集合。保存不得复用组件挂载时的树，也不得用保存瞬间的另一份树重新解释用户曾经看到的内容。服务器响应再按最新树投影回编辑器，并返回下一份快照的隐藏集合。

提交结果只由权威 mutation 决定。mutation 返回版本即为 committed，明确冲突或校验错误为 rejected，客户端没有收到响应则保持 unknown 并重放同一 pending；mutation 之后用于编辑器投影、树刷新或缓存展示的 enrichment 失败不得把 committed 改写成 rejected。receipt 必须绑定服务器在展示投影前计算的不可变逻辑 payload 指纹，并保存该 submission 实际提交成功的 Page 基线；同一 ID 只有 payload 一致才可重放，重放返回其精确 committed baseline，而不是可能已经更晚的当前 Page。回执的常见路径只保存版本、generation 和时间；字段可由指纹绑定的请求重建，只有干净合并改变了请求结果、请求省略了标量字段，或服务器为存储安全补回了编辑器不可见投影内容时，才保存差异 override，不能每次自动保存都复制整页正文。收到回执时，客户端以 submitted 为祖先，把请求之后的本地尾部 rebase 到该精确 committed baseline；不重叠的字段、块或格式继续自动保存，重叠修改才保留旧祖先并进入显式冲突。不同 ID 即使页面字段相同也仍是不同逻辑提交，因为它可能携带不同的 revision 摘要。

真正冲突时服务器版本保持权威，界面提供带属性、文本、格式和块类型上下文的只读 diff。用户只能复制本地内容、回到服务器版本继续编辑，或丢弃本地草稿；不提供整页“保留我的版本”写回。权限丢失和页面删除会终止后台 autosave，但本地内容仍可复制。

本版不引入 Yjs、operation log、presence、离线队列或多人实时协作。IndexedDB 层通过页面 UUID 和可版本化 record 隔离在编辑器边界，未来可由 Yjs persistence 替换，而不用改变服务器页面的公开语义。
