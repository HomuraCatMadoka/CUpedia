# ADR 0042：新增设施直接选址，保留原草稿

状态：Accepted

取代 ADR 0041 中新增设施暂存 Building 候选后再次确认的交互；精确 provider mapping、稳定 Building 身份和禁止按距离推断归属的规则继续有效。

## 决议

用户在新增面板的建筑目录或地图上主动点选已映射 Building，即明确选择该建筑，直接进入设施表单。浏览时仍先打开建筑卡，由卡片入口带入建筑与当前楼层。

“更改”进入临时选址阶段，原位置、楼层和类型保留到新位置被选定。返回填写不修改原草稿；重选同一建筑保留楼层，换建筑只清除楼层。新增只支持建筑内设施，不提供室外与坐标入口。楼层从建筑已有目录选择，资料尚缺时可留空；不在设施表单中创建楼层。已有室外设施仍可查看与修改。

未匹配的热点只作为名称和位置参考，可给出名称匹配的建筑入口，但须由用户主动选择，不能据此写入映射。用户可继续搜索本站建筑，或将缺失建筑作为公开 Map Note 提交；该反馈不创建 Building、Place 或 provider mapping。反馈结束后仍可继续原设施草稿。

选建筑与取消重选共用编辑会话的镜头命令。展示表单时建筑须在面板之外可见，取消恢复原位置。微调与恢复不保留跨步骤的移动动画。

没有携带类型的新增入口要求用户选择设施类型；类型未选择属于草稿状态，不作为发布事实。反馈缺失建筑时，在地图上明确确认图钉位置；移动地图后须重新确认，不能提交先前暂存的坐标。

多数设施沿用类型默认名，保持新增表单精简；课室须填写可辨认的编号或名称，不能以泛称“课室”发布。表单显示同建筑、同楼层、同类型的现有设施作为非阻断提示，帮助用户判断是否重复，但不把这些字段当作 Place 唯一键。

## 后果

新增中的一次主动点选承担位置确认，不增加第二个确认按钮。位置修改和设施发布仍是两个明确动作；切换选址模式不会破坏已填写内容。

建筑目录中的已知楼层应附官方来源，不从最高楼层猜测所有楼层。课室等设施按 Building/Floor 归属，建筑卡直接展示。地图设施卡只展示常用信息与操作，来源和核实记录保留在详情页。

建筑的已知楼层目录独立于设施列表：即使尚未收录设施，建筑卡仍允许选择楼层，并将该楼层带入新增表单。各视口统一使用紧凑楼层选择器；建筑卡直接列出筛选后的全部设施，并在卡内滚动，不再设置单条预览或“查看全部”。空楼层显示“暂未收录”，不能回退到其他楼层的设施。

搜索完整课室编号但尚未收录时，可把匹配到的建筑作为建议。用户从该建筑新增设施，搜索词直接带入课室编号，设施类型固定为课室；用户仍须自行确认楼层后发布。
